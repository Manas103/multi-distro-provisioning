First-boot configuration timing, Ubuntu 22.04, TCG software emulation (see README Honest
framing: this host's AMD SVM is not exposed to the WSL2 VM, so /dev/kvm exists but cannot be
used; boot_and_verify.sh falls back to -accel tcg -cpu max automatically).

Both runs poll the host contract (pipeline/verify_contract.py) every second from QEMU launch
and report the elapsed time at the first fully-passing check, not merely when SSH answers.

RESULT: 280.4s -> 55.4s (5.06x), both under TCG software emulation on this machine.
Claimed 4m10s (250s) -> 38s; measured 280.4s -> 55.4s. The relative shape of the claim holds
(most of first-boot time under the naive approach is package installation, eliminated by
baking packages into the image ahead of time); the absolute seconds are higher in both
directions than a KVM-accelerated host would measure, reported honestly rather than adjusted
to match.
